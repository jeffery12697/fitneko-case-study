# 2026-08 — Phase 22b (part 2): the sticker wall — achievements you can look at

*Phase 23 built the achievement machinery; unlocks paid out credits and sent a card, and that was it. This batch gives them a place: a 3×3 sticker wall in the MINI app, one hand-drawn coach-cat sticker per achievement, with locked ones hidden behind ghost silhouettes and a question mark. Two days after shipping, a v2 made the unlocked stickers* move *— each one plays a five-second animation — and flipped the locked treatment from "greyed-out preview" to full mystery. Shipped as PR #112 and #113, zero backend changes in the v2.*

## The problem

Achievements that only exist as a payout are bookkeeping, not motivation. The wall had to be worth opening: something to collect, something to show off, something locked to be curious about. That made this the first phase where *art direction* was on the critical path — nine stickers had to exist, look like the same cat, and survive a 110-px grid tile — and the first where a shipped design decision got reversed by looking at the real thing on a real phone.

## Decisions

**The Go catalog stays the single source of truth.** The achievements endpoint returns everything the wall needs — bilingual names, unlock hints, progress counts against declarative targets — and the frontend owns exactly one thing: mapping achievement IDs to art. An ID the frontend doesn't recognize renders as a paw-print placeholder instead of crashing the wall, which is the forward-compatibility window Phase 24's new achievements will ship through: backend first, art later, nothing breaks in between.

**Art is a gate, and the pipeline is disposable-friendly.** Nine stickers came from a shared brand-guide opener plus one action sentence per achievement, generated white-background, then flood-filled transparent and crushed to PNG8 (~70–95 KB each). The first batch was auto-trimmed to content — and on a real device the nine cats were visibly different sizes, because trim rewards compact poses and punishes wide props. The fix was the opposite of clever: keep the full 1024² canvas, never trim, let the source composition do the sizing. Asset pipelines get real-device review like code gets code review.

**Mystery beat progress — reversing a shipped decision in a day.** V1 shipped locked stickers as greyed-out previews, on the theory that seeing the pose sells the goal. On a real wall it just looked like the finished collection with the saturation off. V2 flipped it: locked art renders as a near-invisible silhouette under a large "?", names and progress bars stay, and tapping a locked tile shows the unlock condition — every tap gets a payoff, either a reward or a teaser. The reversal is recorded in the spec as a decision that overrides the earlier one, so future readers see the two decisions fight instead of silently contradicting each other. A hard no-leak rule came with it, enforced in tests: no state combination may ever render a locked sticker unfiltered, and a locked tile never mounts a `<video>`.

**Real animation, not CSS wiggle — with a full retreat path.** Each unlocked sticker got a five-second animation clip (960² source, recompressed to 640² at ~200 KB), lazy-loaded only when its lightbox opens: the PNG shows instantly, the video takes over seamlessly on `canplay`, plays once, freezes on its final frame — which matches the sticker pose — and replays on tap. Every failure mode (no clip, load error, webview autoplay refusal, reduced-motion) falls back to the static PNG. The whole-branch review before merge caught the best bug of the batch: React StrictMode's dev-mode double-mount ran the cleanup that strips the video's `src`, killing the feature in every dev session — and since the e2e suite boots the dev server, the passing playback test was testing a corpse. One `isConnected` guard fixed it; the reviewer verified the fix by deleting it and watching the regression test go red.

## Hindsight, honestly

- **Backend first, wall later was the right sequence.** The achievement machinery shipped in Phase 23 and ran for days before the wall existed; by the time the wall was built, the unlock logic was proven and the whole phase became an almost purely frontend project against a finished API. The catalog-driven design is what made that split safe to begin with.
- **The AI art pipeline is now an assembly line.** The same recipe — a shared brand-guide opener plus one action sentence per asset, then a deterministic post-processing pass — worked twice in a row, first for the nine stickers and again for the nine animation clips. Art used to be the thing that blocked a phase; now it's a repeatable production step.
