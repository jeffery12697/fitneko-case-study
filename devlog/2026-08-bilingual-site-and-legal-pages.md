# 2026-08 — The English site, the legal pages, and a mailbox that has to actually work

*Three things shipped in one round, and they turned out to be one thing: the site got a full English half, the terms/privacy/refund pages got rewritten to stop claiming things the code doesn't do, and the MINI app finally went live on its own domain. The connecting thread is that all three are promises made to strangers — so each one needed a test, a mailbox, or an environment boundary standing behind it.*

## The problem

The public site existed in Traditional Chinese only, and the three legal pages were short enough to be dangerous. A payment review reads them, but so does anyone deciding whether to hand a chat bot their meal photos — and the privacy policy said the product doesn't share data with third parties, which is not true of any product that calls a vision API. That sentence wasn't a lie anyone told on purpose; it's the sentence a first draft writes before the architecture exists. By this point the architecture existed, and the page hadn't caught up.

Meanwhile the MINI app was still serving from the provider's URL while every other endpoint had moved to the owned domain, and the site's English readers had nothing at all.

## Decisions

**English gets its own URLs, and nothing auto-detects anything.** `/en/` mirrors the seven page types with complete standalone HTML per page. No redirect based on browser language, no cookie remembering a choice, no two-language DOM with one half hidden. The reasons compound: the site is deliberately zero-build-step, so a template engine was never on the table; a hidden-half DOM would double every page's weight and ship Chinese text to English readers; and a JS-driven language switch would break the one property a legal page must have, which is being readable with JavaScript off. The only dictionary is for the homepage hero's animated chat, because that copy genuinely is generated at runtime — and an unknown `lang` falls back to Chinese so a missing string can't freeze the animation.

**The 404 has to pick its own language, because the CDN can't.** CloudFront's custom error response points at one fixed body, so it cannot choose between a Chinese and an English 404. The root 404 therefore carries both, defaulting to Chinese, with a minimal inline script that inspects the original request path before first paint and switches the visible copy, `lang`, title and description if it starts with `/en/`. It's marked `noindex`, and it degrades to Chinese if the script never runs. No Terraform change, no second distribution behavior — the constraint got absorbed into one page instead of into the infrastructure.

**The legal pages now describe the system that exists.** "We don't share with third parties" was replaced with what actually happens: named categories of processors — messaging, model providers, cloud and database hosting, the payment gateway — and the regions the data is processed in, which is four countries once you follow the vendors honestly. The pages also state that user content is not used to train general-purpose models, and that changing *that* would require updating the policy and obtaining separate consent first, because a policy that pre-authorises a future decision isn't a disclosure.

They also don't overclaim in the other direction. The operator is disclosed by name with a support address, but the first version withholds a street address and phone number, which is a known gap against Taiwan's e-commerce disclosure expectations — so the pages must not assert full compliance anywhere, and the spec says so explicitly. Same discipline on refunds: the policy states the goodwill window and the mechanism, and pointedly does *not* assert that the statutory withdrawal right is excluded for a service that starts immediately. That's a legal characterisation, and I don't have counsel, so the pages say the rules don't limit rights that law doesn't allow to be waived, and leave it there.

**Bilingual parity is a test, not a habit.** A Go package sits in the normal test suite and asserts the contract: all seven page pairs exist; each page's `lang`, canonical, `hreflang` set and Open Graph locale agree with its own URL; English pages' internal links and legal cross-references stay inside the English namespace rather than quietly pointing home; no visible Chinese copy survives on an English page; the hero has copy in both languages; and the legal pages contain the specific disclosures that were agreed. This earned its keep immediately — when the branch fell behind `main`, four things had silently diverged on the English side, including the call-to-action destination and the sticker wall's cell count, and the parity tests named all four instead of me finding them later on a phone.

**The support mailbox was a release gate, not a task.** The pages publish one address as the channel for refunds, data-rights requests and complaints. An address that bounces turns every one of those promises into a dead end, so the rule was that the mailbox had to be verified receiving *and* replying before the new legal pages could deploy. It runs on the domain's own mail records through an existing paid personal service — zero marginal cost — and the reply passes authentication with the signature carrying this domain's key rather than the provider's, which is the detail that decides whether the mail is *from* the brand or merely *about* it.

**Production gets its own MINI app channel.** The original plan shared one channel between development and production using its sub-environments. That plan was wrong, and the reason is specific: while the channel is unverified, settings made in the development side propagate to the published side — so one shared channel means there is no dev/prod boundary at all, just two names for the same configuration. Two channels, two LIFF ids, and the environments can't reach each other.

## What the process caught

The English pages were rendered in the CJK font, and it looked broken in a way that took a while to name. In a CJK font the curly quotes and the middot are *full-width* glyphs — at a 17px size they occupy 17px, where the Latin font gives them a third of that — so English prose came out pocked with kanji-width holes. English pages now override the font family, and a static check pins the pairing by language.

The same round found a latent clipping bug that both languages had and only English tripped. The homepage chat panels used a fixed height with hidden overflow; English content overflowed it by around 20–26px, silently cutting the last message of the hero conversation. Chinese had about 12px of headroom, which is to say it was one copy edit away from the same bug. Switching to a minimum height fixed both.

And a measurement trap worth writing down: elements with an entrance animation report their *first-frame transformed* size from `getBoundingClientRect()` in an automated browser, because the animation clock doesn't advance there. It reads exactly like a layout bug — I chased a nonexistent 1.2× height before realising the number was the keyframe, not the layout. Disable animations before measuring anything.

Going live on the MINI app's own domain surfaced one more: a newly created channel doesn't grant the OpenID scope by default. The symptom is cruel — the profile call works, so the user's name renders correctly, while every authenticated request fails because the id token comes back null. The only honest clue was one log line in the API function about a missing bearer token. It's a checkbox in a console, and it has to be ticked manually per channel.

## Hindsight, honestly

- **Writing the privacy policy honestly was an architecture review I didn't plan.** Enumerating the processors and regions forced me to state, in public, exactly what leaves the system and where it goes — which is a question I'd answered in code long before answering it in prose.
- **The parity test paid for itself within one merge.** Four silent divergences on the English side, caught by assertions rather than by a phone. Bilingual content without a contract test is just two documents drifting.
- **Deciding what *not* to claim was harder than writing what to claim.** Both the compliance gap and the refund characterisation were tempting to paper over with a confident sentence, and refusing to write those sentences is the part of this round I'd defend hardest.
